# M1.1 Shadow Observation Cost Reduction

Independent follow-up to `ead8a452ca`. Default setting remains false. M1.1 changes
only shadow observation work/reporting; producer hooks/categories and physical
resolver/guest/GPU behavior are unchanged. No GPU commands, waits, ownership,
imports, gather/scatter, dirty state or retirement changes.

## Motivation and implementation

Device M1-on SMO stutter recovered when only M1 was disabled. A captured SMO
report summed 33.61s in Observe versus 3.37s in Resolve. Millions of 128-entry ring
evictions and broad overlap comparisons suggested reducing observation work,
not changing guest correctness or per-range generation infrastructure.

1. **Selected operations:** default period 64. The first preparation and first
   outside-preparation event are inspected; subsequent sequence numbers are
   deterministically mixed and approximately 1/64 selected. All input hooks still
   count observations, write intents, bytes and sizes by the same six categories.
   Unselected inputs return before clocks, cache lookup, mapping locks or resolve.
   Outside events have a separate sequence/domain so clears/copies don't inherit
   a stale draw decision. This is sampled coverage, not unbiased population inference.
2. **Within-operation dedup:** exact manager/GPU VA/size/kind key, expected DAddr,
   access intent and operation ID. Only a previously successful same-operation
   registration with unchanged atomic lifetime/generation hints may skip repeated
   diagnostics. ReadOnly->Writable is different input and always inspected when
   selected, upgrading potential-write information before geometry comparison.
   Mapping change, expected-DAddr change, failure or next preparation prevents
   dedup. Dedup is **not** paired-lock validation/current registration; its skipped
   event is explicit unknown coverage. A remap can still occur after atomic hints.
3. **Bounded cache hint:** 256 numeric slot hints (512B) accelerate repeated keys;
   full key verification precedes reuse. Collisions/stale hints after eviction
   fall back to the 128-entry search. No raw manager/producer ownership reference,
   unbounded map or eviction change.
4. **Span geometry:** equality of two linear DAddr translations holds to the end
   of their captured spans. Advance to the nearest span/physical overlap end,
   rather than visiting each 4KiB page in a large equal overlap. Later DAddr breaks,
   partial/split/repeated physical segments and different manager/epoch geometry
   remain checked under the existing 4096-probe loss budget. Missing provenance
   records comparison loss instead of treating address0 as equal.
5. **Metadata accounting:** maintain retained vector-capacity bytes on slot
   replacement. Peak tracking becomes O(1), avoiding three 128-entry walks per
   fresh resolve. Existing observed-payload/allocator-peak limitations remain.

`PhysicalShadow(1)` is available to isolated tests for exact unsampled validation;
the renderer constructs the default period 64 policy. No extra frontend setting.
The existing optional shadow allocation and disabled branches stay unchanged.

## Coverage definitions and denominators

All producer sources/classification/exclusions are the M1 contract. Sampling does
not reclassify CPU/NCE/raw, query, DMA/inline/upload or unmarked texture producers
as covered. Every report retains `coverage=unknown` and adds `measurement=sampled`.
Zero cross-DAddr/manager witnesses cannot exclude rare/short-lived aliases.

For each category:

```
observations = sampled_out + deduplicated + inspections
inspections = registrations + unresolved
write_intents = sampled_out_writes + deduplicated_writes
              + registered_writes + unresolved_writes
unregistered_write_intents = write_intents - registered_writes
```

`observations/write_intents/bytes/max_range/size_buckets` cover **all inputs**, as
before. `registrations/registered_writes` require actual successful selected
resolution/paired validation and provenance checks; skipped/dedup writers are
not silently called registered or conflict-free. Their write intent is recorded
before either early return. Registered segments/splits are inspection subsets.

`dispatches = sampled_dispatches + skipped_dispatches` counts all completed
preparation attempts, not successful GPU dispatches. Outside observations split
into selected/skipped. `timed_observations = inspections + deduplicated` summed
across categories. Resolve histograms/invalidations/requeries describe actual
selected inspections, not missed events. Dispatch quantiles include selected
preparations only; skipped zeroes don't dilute P95/P99.

`observer_ns` measures selected bodies, including lookup/dedup work, excluding
input counters/gating and visitor/logging work. It is not total enabled-M1 cost.
This scope is printed in the sampling report; old M1 total timing denominators
must not be reused. Alias encounter denominator remains `registered_observations`
(now sampled inspections). Pair/cardinality numbers are bounded historical
sampled geometry, never data versions/current ownership or a full dispatch survey.
Sampling, dedup, eviction, comparison/cardinality caps and unresolved cases are
all exposed. Do not extrapolate these biased/windowed samples into a proof that
an unobserved writer or alias doesn't exist.

## Validation and performance evidence

The correctness suite uses production observer, report, binding/texture hooks and
extracted resolver/GMMU with fixture mappings. Full-rate policy preserves existing
split, epochs, different-DAddr/manager, lifetime, fault/provenance and budget tests.
M1.1 adds:

- Same-operation readonly/read duplicate/writable/write duplicate: every write
  intent counted, first writer inspected and potential-write state promoted.
- Generation and expected-DAddr changes force another inspection; failed
  provenance isn't eligible for dedup; next operation revalidates.
- 4096 preparations plus 4096 outside writes: conservation equations, skipped
  writes retained as unknown, selected histogram denominators and zero query/timer
  work on skipped operations.
- A rare skipped writer following a readonly registration is counted but remains
  unknown; old readonly geometry does not count as a registered writer.
- 16MiB equal overlap costs one span step; a later discontinuous DAddr mapping
  inside a physically contiguous segment still detects a different-DAddr alias.
- Existing bounded-cache eviction, manager isolation, OOM containment, real-fmt
  sampled/unknown report and disabled-path checks.

```
python tools/physical_shadow_tests/run_tests.py --cxx g++

```

Synthetic CPU-only workload runs the actual old/new observer with production
fixture mappings: four 16MiB GPU aliases, repeated writable intents, 500 preparations.
Windows MinGW O2: same 8000 inputs/writes; old 88.05ms versus M1.1 ~0.38ms. New policy
selected 10 preparations, 7840 inputs sampled out, 120 dedup, 40 registrations; all
input/write counts preserved. Old 7999 comparison drops, new 0; new 114 span steps.
Linux GCC O2: old ~119.0ms versus M1.1 ~0.30ms, with the same work counts.
This deliberately favorable repeated-large-alias workload demonstrates work
reduction, **not SMO FPS improvement or an Android speedup claim**. Timings depend
on host/compiler; don't gate regressions on an elapsed-time ratio. Real-device
off/on retest remains necessary. No local Android full build.

Validation completed on Windows MinGW and Linux GCC: shadow correctness suite,
all nine existing gather/buffer-cache runners (including CPU-write and unmap
preservation); Linux physical resolver and owned DMA snapshot suites. Linux
shadow ASan/UBSan passed. The actual Vulkan rasterizer translation unit compiled
with isolated platform/dependency shims; this is not a full Android build/link.
The report test uses real fmt rather than stub formatting.
